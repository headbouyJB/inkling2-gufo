# Milestone M1: a correct text-only HIP runner

Status 2026-11-21, Gufo v0.35.0 (`0260e11`), a Ryzen AI MAX+ 395 (gfx1151, 128 GiB) machine. Everything below was measured; what
was not measured is listed at the end. Target met: mean KL against llama.cpp is 1.5e-3 on both
checked files, at the level of llama.cpp's own GPU-versus-CPU noise (2.4e-3, below).

## What exists

| Piece | Where |
| --- | --- |
| Simple HIP kernels, one per op, F32 activations, native weight formats (no requantisation) | `src/hip/kernels.hip`, `kernels.hpp` |
| Forward pass: 48 visits, block attention residual, loop controllers, short convs, relative-bias attention with sink and SWA ring, SITU MoE, softcapped head | `src/engine.cpp`, `engine.hpp` |
| Gufo runner: descriptor, claim, plans, tokenize/render, prefill, select/advance, cache adapter | `src/runner.cpp` |
| Streamed-text framing and the tool dialect that matches it | `runner.cpp` (`Piece`), `src/stream_dialect.hpp` |
| Oracle: teacher-forced top-64 + logsumexp dump, llama.cpp counterpart, comparison | `tests/oracle/oracle.cpp`, `llama_dump.cpp`, `tools/compare_dumps.py` |
| Dev loop, serve smoke, functional-suite driver | `BUILD.md` section 3, `tools/*.sh`, `tools/smoke.py` |

Weight types with a kernel: F32, F16, BF16, Q8_0, NVFP4 (+ per-expert `.scale`), Q5_0, Q4_K, Q5_K,
Q6_K, IQ4_NL, IQ4_XS. Weights are uploaded with `hipMemcpy` from the mapped GGUF (16.4 GiB for
UD-Q4_K_XL in 2 to 4 s warm; falls back to managed memory when the device heap is full). Kernel
shape: a wave32 per weight row, lanes stride over 16 or 32-element items that are dequantised into
registers, 1 or 8 tokens per block row-tile; MoE groups (token, expert) pairs by expert on the
host after reading back the router's top-8 (one sync per visit); attention is one block per
(token, head) with an online softmax, the relative bias looked up per key by distance
(`R_h . B[:,d]`, zero beyond 1024), the sink as a zero-value key.

State per session (`Session`): 48 visit slots, 8 global KV (`max_context` rows, f16) and 40
sliding-window rings of 1024 + ubatch (1536) rows, conv history 48 x 6656 x 3 F32. At `--context
32768` that is 1.07 GB + 0.25 GB + 3.8 MB. Activations and MoE staging are shared scratch (about
0.6 GiB at ubatch 512).

## Oracle check (llama.cpp e412c6f + PR #32704, CPU backend)

Same 9,300 GPT-style tokens (first 9,300 of `$CORPUS_DIR/wiki.test.raw`, plain text), same GGUF,
teacher forced; one run covers the 1024/2048 cases, SWA eviction (position >= 1024) and tau > 1
(position >= 8192). KL(llama || ours) over llama's top-64 plus one tail bucket
(`tools/compare_dumps.py`; a lower bound of the full KL, the tail mass is small).

UD-Q4_K_XL (`Mainline_Support`; NVFP4 L0-19, Q8_0 L20-23 and dense, BF16 and F32 small tensors):

| positions | mean KL | max KL | top-1 agree | mean abs logit diff (top-64) |
| --- | --- | --- | --- | --- |
| all 9,300 | 1.47e-3 | 0.212 @ 8235 | 98.19 % | 0.116 |
| 0-1023 | 1.29e-3 | 0.033 | 97.95 % | 0.133 |
| 1024-2047 | 1.69e-3 | 0.143 | 98.24 % | 0.132 |
| 2048-4095 | 1.24e-3 | 0.044 | 98.14 % | 0.095 |
| 4096-8191 | 1.44e-3 | 0.098 | 98.34 % | 0.107 |
| 8192-9299 | 1.92e-3 | 0.212 | 97.92 % | 0.159 |

UD-IQ4_XS (adds Q5_K, Q4_K, Q5_0, Q6_K, IQ4_NL, IQ4_XS): mean KL 1.49e-3, max 0.288, top-1
98.31 % over the same tokens (ranges 1.15e-3 to 1.68e-3).

Decode path (one token per `Forward`, T = 1 kernels, first 600 tokens, Q4_K_XL): mean KL 1.17e-3,
max 0.020, top-1 97.83 %; the prefill path gives 1.29e-3 on the first 1024.

How to read 1.5e-3: llama.cpp quantises activations to int8 (Q8_0/Q8_1) in every matmul; we keep
F32 activations. To size that noise, the same file through llama.cpp's own HIP backend against its
CPU backend, same tokens: mean KL **2.38e-3**, top-1 97.73 %. Our engine sits closer to the CPU
oracle than llama's GPU backend does, and the error is uniform over positions, with no step at
1024 (SWA eviction) and only a small rise past 8192 (1.9e-3 against 3.1e-3 for llama HIP there).
No per-visit bisection was needed, so no hidden-state dump was compared (the tap
`Engine::SetTap`/`--tap` exists for it; unused).

## Serve smoke (`gufo serve llm --context 32768 --sessions 1`, 127.0.0.1:5830, dev build)

- chat: "Say hello in one short sentence." -> reasoning block, content `Hello, nice to meet you.`
  (finish `stop`).
- reasoning effort: `reasoning_effort: none` renders the template's level 0.0 and opens the answer
  block in the prompt (no thinking); `high` / default think first. Both answer `391` for 17*23.
- tool call: `get_weather(city=Paris)` returns a parsed `tool_calls` entry, `finish_reason:
  tool_calls`; `tool_choice: required` with reasoning off also works (stops suite).
- speed (naive kernels, one session, non-streaming client wall time): prefill 172-197 tok/s on a
  3,435-token prompt, 118-135 tok/s on 20-30 token prompts (startup dominated); decode 18.8-19.4
  tok/s (about 50 ms per token). The oracle's batched pass runs 145 tok/s including full-vocabulary
  logits for every position. llama.cpp HIP on the same file: ~24 tok/s decode. These are the baseline
  for M2; nothing was tuned.

## Deviations from the spec and from the in-tree runner

1. **No prefix reuse.** `Descriptor().capabilities.prefix_reuse = false`; the cache adapter
   (`Inkling2Adapter`) hands out one session per slot, declares `continuation = false` and one
   dummy private component, and refuses capture/restore. The pool re-prefills every request from
   position 0. Needed for M2: components for the 8 global KV slots (append rows), 40 SWA rings
   (`kWindowRows`, which no in-tree model uses yet), conv history (private state) and checkpoints at
   exact token boundaries; `PlanPrefill`, `PrefillThrough`.
2. `max_layer_groups = 1` (prefill is not split by layer group; a 512-token pass takes ~3.5 s),
   `max_yield_decode_width = 1`, serial plan only, no `DecodeBatch`, cancellation is only checked
   between requests, no DSpark / speculative decoding, no images (`supports_vision = false`).
3. **Streamed text is not the literal token text.** The host builds the response from the runner's
   pieces (`incremental_text_is_exact = true`), and its parsers know one reasoning span plus
   content. So `Piece()` withholds framing the host cannot use: `<|message_model|>` and a text
   block's `<|content_text|>`/closing `<|end_message|>`, and the first (function name) copy of a
   tool call. Reasoning reads `<|message_model|><|content_thinking|>R<|end_message|>` (open/close in
   `ReasoningDelimiters`). `Decode()` stays literal. Reason for the tool part: Gufo v0.35.0's
   `ToolSyntax` can name the function only once, the model writes it twice, so the grammar is exact
   for `<|content_invoke_tool_json|>{"name":N,"args":...}<|end_message|>` and `stream_dialect.hpp`
   rebuilds the canonical call for the parser in `src/text`. A newer Gufo with name repetition could
   stream the literal text instead.
4. **Reasoning off.** Gufo's `enabled=false` / effort `none` must mean no reasoning; the template's
   level 0.0 does not stop the model from thinking, so `ToRenderOptions` appends
   `<|message_model|><|content_text|>` (no tools) or a finished empty thinking block (tools). The
   model can still think when tools are present and the call is not forced. Edits to the text
   front-end: `Prefix::kEmptyThought` (chat_template), the prefix selection in `gufo_adapter.hpp`
   (`tests/text` re-run after the edits with g++: all render, tokenisation and decode goldens pass; one `StreamDecoder` check failed, `text_tests.cpp:206` invalid UTF-8 release order: a test bug, fixed in M2, see docs/dev/M2.md "Also fixed")
5. The cache ledger needs `retained_snapshot_*` bytes in the claim even though nothing is
   retained (`HostSnapshotBudgetBytes/CeilingBytes`), otherwise loading fails with "RAM cache
   budget exhausted".
6. Weights upload is a plain chunked `hipMemcpy`, not `hip::WeightUpload`; the oracle tool links the
   same engine, so it does not need the Gufo pipeline.
7. A request-level model id is required by the server (`"model": "inkling-2-mini"`).
8. The harness's `conversation` suite assumes thinking is binary; with effort low/minimal Inkling
   may answer without reasoning (seen in the first runs, before the empty-thinking prefix): that
   assertion is model behaviour, not an engine matter.

## Not verified

- `--sessions > 1`, concurrent requests, cancellation, long generations near `--context`.
- Contexts above ~9.3K tokens (the global KV and bias beyond 1024 were exercised to 9.3K only).
- Quality of generated text beyond the smoke prompts (KL and top-1 are the evidence); no PPL run.
- Disk/RAM cache, speculative decoding, images (all off).
- Q4_0/Q4_1/Q8_K-family and other types outside the probe's list (they are refused at probe time).
